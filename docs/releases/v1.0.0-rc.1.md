# Open Artifacts Foundation v1.0.0-rc.1

This is the first production-engineering release candidate derived from fixed
upstream baseline `a03a8c3721dd0021c78ea24533d6f7a7f4af07b3`. The tag is
created only by an approved immutable release run against a clean full commit;
this document does not claim that an uncommitted workspace is a tagged release.

## Highlights

- Atomic visible publication across immutable R2 content and one D1 CAS commit,
  with idempotency, failure recovery and reconciliation.
- Numbered schema migrations through v5; production requests validate and never
  execute DDL.
- Crash-safe CLI state and complete credential rotation/revoke/recovery.
- Remote-safe auth defaults, rate limiting, exact quotas, security telemetry,
  backup/restore and resumable repair.
- Live Draft/Checkpoint semantics with immutable history and rollback-as-copy.
- Protocol v1 schemas/golden fixtures shared by Worker, CLI and Viewer.
- Modular Viewer/CLI composition, deterministic browser runtime, WCAG 2.2 AA
  checks, quality budgets and production-shaped environment validation.

## Compatibility and upgrade

- HTTP and Live clients negotiate `Open-Artifacts-Protocol: 1`. Missing header
  is accepted as v1; an unsupported explicit version receives structured 426.
- Apply `migrations/0001` through `0005` before deploying the Worker. Reapplying
  through Wrangler’s migration ledger is safe.
- CLI Manifest v2 and existing stable artifact URLs remain supported. Published
  historical versions retain their content hashes.
- Preview, Staging and Production require distinct D1, R2, Analytics Engine,
  rate-limit and Worker identities plus secrets named by the environment policy.

## Known limits

- P0 supports internal/invited teams on Cloudflare Workers/D1/R2/DO, not public
  multi-tenant SaaS or a second production provider.
- Rate limiting is a soft burst control; exact quota is enforced separately.
- Password protection is client-side/zero-knowledge and cannot provide
  server-side password recovery or guess telemetry.
- Production deployment, reviewer signatures and Canary observations are
  external release gates and are never fabricated by repository tests.

## Rollback

Freeze the affected surface first. A previous Worker may be redeployed only if
it supports schema v5 and the active `LiveObject` lifecycle. Keep additive
tables/columns and roll forward for incompatible changes. Never rewrite a
historical Blob/version. Restore D1 into an isolated database and validate it
before switching a binding. Follow the [rehearsal](rehearsal.md),
[migration](../runbooks/migrations.md), [restore](../runbooks/restore.md) and
[Canary](canary.md) records.

## Required sign-off

Platform, CLI, Viewer, Security and SRE owners must approve the same immutable
manifest and Staging receipt. Production additionally needs the protected
Environment reviewer and Product owner. Missing signatures block tag
publication/promotion.
